### 2. TypeSelector Keystroke Auto-Save Bug

**Issue**: TypeSelector was saving every keystroke as a custom type, creating types like "g", "ge", "gen", "generator".

**Root Cause**: The `handleNewTypeChange` function was calling the API on every `onChange` event.

**Solution**:
- Separated input handling from save logic
- Added explicit "Save" button with "Save/Cancel" controls
- Implemented keyboard shortcuts (Enter to save, Escape to cancel)
- Auto-lowercase conversion on input

**Files Modified**:
- `src/renderer/components/shared/TypeSelector.tsx` (lines 57-129)

**Technical Details**:
```typescript
// Before: Auto-saved on every keystroke
onChange={(e) => {
  const newValue = e.target.value.toLowerCase()
  setNewTypeName(newValue)
  onChange(newValue) // This triggered immediate save
}}

// After: Requires explicit save
const handleSaveNewType = async () => {
  if (!newTypeName.trim() || !property) return
  // Only saves when button clicked or Enter pressed
}
```

### 3. Custom Type Delete Not Updating UI

**Issue**: Clicking "Delete" on individual custom types worked in database but UI didn't update without app refresh.

**Root Cause**: Settings component used `property` prop from parent which doesn't update when queries invalidate.

**Solution**:
- Added local property query in Settings component: `useQuery(['property', property.id])`
- Created `currentProperty` variable using local query data
- Updated all references to use `currentProperty.custom_entity_types`
- This ensures UI automatically updates when query is invalidated

**Files Modified**:
- `src/renderer/components/settings/SettingsView.tsx` (lines 16-24)

**Technical Details**:
```typescript
// Local query subscription
const { data: localProperty } = useQuery({
  queryKey: ['property', property.id],
  queryFn: () => window.electronAPI.properties.findById(property.id),
  initialData: property
})

// Use local data for reactive updates
const currentProperty = localProperty || property
```

## Developer Notes

### Custom Types Architecture

Custom types are stored at the **property level**, not panel level:
- Property model has `custom_entity_types: string[]` field
- Shared across all panels within the same property
- Default types (outlet, switch, light, appliance, hvac, other) are hardcoded and always available

### State Management Pattern

Consistent state management for inline editing forms:
1. `isEditing` boolean flag
2. `newValue` state for input
3. Save/Cancel handlers
4. Keyboard shortcuts (Enter/Escape)
5. Immediate visual feedback with loading states
6. Proper query invalidation after successful operations
